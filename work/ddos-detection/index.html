DDoS Detection

A 12-class detection study on a balanced CIC-DDoS2019 holdout. The headline number is 95.26% accuracy; the more important finding is that one attack class still fails a third of the time.

Context

Multi-class intrusion detection has a familiar evaluation problem: a strong aggregate score can hide a class that the model rarely gets right. For a security product, the rare class is often the one that matters.

I worked on a transformer-based classifier for 12 traffic categories from CIC-DDoS2019, using a balanced 14,400-flow holdout. The goal was not to claim a production detector. It was to build the full path — preprocessing, feature grouping, training, class-level evaluation, and interpretation — and report what the model actually did.

The model, precisely

The architecture is a feature-view transformer, not a packet-level transformer. Derived flow features are grouped into four families, encoded separately, projected into a shared width, concatenated, and passed through a transformer encoder. Pooling is combined with a protocol embedding before the classifier.

  • Temporal features: duration, rate, inter-arrival timing, and flow activity.
  • Spatial features: packet-size and direction statistics.
  • Protocol features: transport and application protocol signals.
  • Statistical features: distribution summaries and aggregate flow statistics.

Evaluation setup

I filtered CIC-DDoS2019 to a 12-class problem and evaluated on a balanced holdout of 14,400 flows. That choice makes class-level comparison easier, but it is not the full, imbalanced dataset. The numbers below should be read as a controlled research result, not as a benchmark against every published detector.

Interpretation

The repository includes attention inspection and integrated-gradients analysis over the feature groups. Those tools help answer which feature family influenced a prediction. They do not prove causality, and they do not turn the model into a deployable security control.

What the code supports

The implementation uses separate attention per feature family, concatenation, and a transformer encoder. The interpretability work is attention and integrated gradients; the repository does not include SHAP or adversarial-robustness results.

Limits

  • Filtered data. The 12-class balanced holdout is not the full CIC-DDoS2019 distribution.
  • Offline only. There is no live capture, latency budget, or deployment evaluation.
  • No adversarial testing. The model’s behaviour under evasion or distribution shift is not measured.
  • Interpretability is diagnostic. Attention and integrated gradients are not a security guarantee.

What I would do next

  • Rebuild the split with group-aware separation so related flows cannot leak across train and test.
  • Evaluate on the full imbalanced dataset and report per-class precision, recall, and calibration.
  • Add an adversarial and drift test suite before making any deployment claim.
  • Measure inference latency and memory on a realistic edge target.

Last verified November 2026. Research code and saved evaluation artifacts are public in the linked repository. The project was not deployed in a production network.
